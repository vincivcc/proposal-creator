# 提问页规格

**所有要用户拍板的事，都放进一份 HTML，不要用对话框问答。**

理由：用户经常攒着一批问题一起处理，对话框一问一答的往返成本很高。
而且光把问题列出来还不够——用户看完还得回对话框打字，等于没省。
所以提问页必须**能勾选、能填、能传图、能一键导出**。

对话框里只留一句：「本批 N 个问题在 `<文件名>.html` 底部。」

---

## 一 · 什么时候出提问页

每个节点结束、需要用户拍板时才出。一次一批，不要边做边问。

| 节点 | 产出 |
|---|---|
| 启动 | 亮全流程节点图（文字即可） |
| 拿不准需求时 | 需求澄清页 |
| ③ 核对之后 | 数据与预算核对清单 |
| ④ 之前 | 风格与素材页 |

---

## 二 · 结构

```html
<section class="q" data-q="Q1">
  <h3>Q1 · 背景走哪个方向？</h3>
  <p class="hint">每组配缩略图，不要只给文字描述。</p>
  <label class="opt"><input type="radio" name="q1" value="A">
    <img src="data:image/jpeg;base64,...">
    <b>A · 深底冷调</b><span>接近参考方案的做法，安全</span></label>
  <label class="opt"><input type="radio" name="q1" value="B"> ... </label>
</section>
```

要点：

- **每个选项配可视化预览**。选风格这件事，文字描述没有意义，必须看图。
  预览图用 base64 内嵌，不要外链——文档要能离线打开、能单独发出去。
- **选项要带取舍说明**，不只是名字。「A · 深底冷调 —— 接近参考方案，安全」
  比「A」有用得多。
- **单选 / 多选 / 填空都要有**。填空只给真正需要用户输入的（品牌名、日期、联系人）。
- 上面这套是「**回答问题**」。如果这一页是让用户**逐条表态**（提纲、逐页内容、数据核对），
  用第三节那个裁决控件，不要用这里的单选——两者形状不一样，别混。
- 文档**单文件、离线可开**，样式内联，不依赖任何外部资源。

---

## 三 · 逐条 / 逐页裁决控件

三个卡点里，**① 提纲、② 逐页内容、③ 数据与预算核对**，本质是同一件事：
把一批条目摊开，让用户逐条表态。**这三处用同一个控件，不要各写各的。**

> 这个控件是补上的。之前 ① 只写了「一个反馈位」、③ 写「可用 / 拿掉 / 要改」，
> 两套措辞导致每次跑出来的东西都不一样——用户会问「怎么和上次不一样」。
> 规格写死之后就不会了。

### 一个节点 = 一份文件 = 一次导出

**一个卡点只出一份 HTML，条目再多也不拆。** 章节之间用一行小标题隔开就够了。

反例：② 每页具体内容按章节拆成 `02-内容-01/02/03.html` 三份。
用户的原话是「粘贴复制反馈的时候容易搞混」——他要复制三段回来贴，
还得记住哪段对应哪份文件，串了都不知道。

导出按钮同理：**一份文件一个导出按钮，一次给全**，不要按章节分几个导出。
用户攒着一起处理，这个前提决定了入口越少越好。

### 三个选项，措辞固定

| 控件 | 含义 | ③ 里的旧措辞 |
|---|---|---|
| `✓ 确认` | 这条通过，按原样往下走 | 可用 |
| `✎ 修改` | 方向对但要改，**选中后展开文本框** | 要改 |
| `✗ 删除` | 整条拿掉 | 拿掉 |

**选「修改」才展开文本框。** 一直摆一个空文本框等于没给结构——用户还是不知道该说什么，
于是要么不填，要么写一句「再改改」这种没法执行的话。

### 未表态 ≠ 确认

默认**三个都不选中**。用户没点过的条目算「未表态」，必须在页脚单独报出来，
**不能默认通过**——卡点是硬关卡，静默通过比漏审危险得多。

页脚固定这一行，随点随更新：

```
共 N 页 · 已确认 N · 待改 N · 删除 N · 未表态 N
```

导出时如果还有未表态的，提示一句：**「还有 N 页未表态——未表态不等于确认。」**
（③ 用「条」不用「页」，其余同。）

### 每个裁决页都要配一个「整体反馈框」

逐条裁决只能表达「这一条行不行」。**但整体的问题——章节顺序、颗粒度、通篇语气——
落不到任何单一条目上。** 用户想说「第二章该挪到第三章后面」，却发现只能在一页上
点「删除」，于是他要么不说，要么在一页的备注里写一句对不上号的话。

所以每份裁决页的条目列表**之后**、导出**之前**，必须有一栏「整体反馈」。三条规矩：

- **就一个大框，不要分类。** 不要拆成「逻辑 / 颗粒度 / 文案」这种格子。
  每份方案的关注点不一样，每个人的说法也不一样，预先分好类等于把你的分类强加给他——
  他真正想说的是第四件事，找不着格子，就不说了。**开放性回答就该是开放的。**
- **框给大**（`min-height` 150px 上下）。它是这一页唯一一处不被结构约束的地方。
- **placeholder 只交代「这里说整体、不是逐页」，不要举例列举**——
  列了就是变相分类，用户会照着你的例子答完就走。

> 这三条是踩出来的。第一版分了「逻辑 / 颗粒度 / 文案」三格，用户的原话是
> 「每个项目以及每个人的反馈可能都不一样……这样反而限制住了」。
> **这是最容易被"优化"掉的地方**——分类看起来更贴心，实际是收窄。

**位置上有个坑**：框放底部是对的（用户得先看完才有整体意见），
但必须在**页面顶部给一个锚点提示**，否则用户读完整页才发现底下有话说，
那时候已经忘了自己要说什么。

### HTML 结构

```html
<div class="item" data-p="P10">
  <h3>P10 · 提纲 / storyline</h3>
  <p>这页要说什么…</p>

  <div class="verdict">
    <label><input type="radio" name="p10" value="ok">   ✓ 确认</label>
    <label><input type="radio" name="p10" value="edit"> ✎ 修改</label>
    <label><input type="radio" name="p10" value="del">  ✗ 删除</label>
  </div>
  <textarea name="p10-note" hidden placeholder="要改什么？"></textarea>
</div>
```

`name` 用页码（③ 用条目编号）。文本框默认 `hidden`，选「修改」时去掉这个属性。

### 导出的字段形状

```json
{
  "逐页裁决": {
    "P10": { "裁决": "edit", "备注": "步骤④拆两页" },
    "P11": { "裁决": "ok" }
  },
  "整体反馈": "第二章和第三章的顺序反了；P13 太满，拆两页。",
  "统计": { "共": 16, "已确认": 1, "待改": 1, "删除": 0, "未表态": 14 }
}
```

`整体反馈` 是一段整文，不是对象，也别分字段。没写就整个键不要出现。

没收到的编号就是未表态，**不要补成 `ok`**。

## 四 · 逐页素材表（每份方案都要有）

每页一行，让用户一次性把所有图的事交代完：

| 列 | 内容 |
|---|---|
| 页码 | `P07` |
| 标题 | 这页的标题 |
| 这页要什么图 | 具体到「产品瓶身正面特写」这种程度 |
| 需求等级 | 必需 / 可选 / 不用 |
| 上传槽 | 拖拽区，右侧即时缩略图 |
| 批注 | 用户自由填写 |

**图非必须。** 没有的页留一个虚线占位框，并在文档里说明「留空也行，
出 PPT 时这一页会走姓名卡 / 纯文字版式」。

## 五 · 上传的两种走法

图片**只落在本机，不上传任何外部服务**。这一点要在文档里写明。

### 主路：File System Access API

Chrome / Edge 在 `file://` 下可用（已验证）。用户选一次 `产出/素材/` 目录，
之后每次拖图直接写进去，文件名就是素材槽名。

```js
dirHandle = await window.showDirectoryPicker({ mode:'readwrite', id:'<项目>-assets' });
// 写：const fh = await dirHandle.getFileHandle(name, {create:true});
//     const w = await fh.createWritable(); await w.write(file); await w.close();
```

要点：

- `id` 参数让浏览器记住上次选的目录，同项目复用。
- `showDirectoryPicker` 不存在（Safari / Firefox）或用户拒绝权限时，
  不要静默失败——**弹提示并说明会自动降级**：
  ```js
  if (!window.showDirectoryPicker) { toast('这个浏览器不支持写文件夹——改用「保存」下载'); return; }
  ```
- 用户取消选择会抛 `AbortError`，这个要**单独判断并忽略**，不能当成失败。

### 降级路：导出 JSON

不支持时，把图片转 base64 打包成一个 `素材包.json` 下载。
之后由 `scripts/unpack.py` 解开：

```bash
python3 "$SKILL/scripts/unpack.py" <产出目录>
```

它会把图写进 `产出/素材/`，并把风格选择和批注存成 `_素材清单.json`。
找不到时会提示找过哪两个位置（`产出/素材/` 和 `~/Downloads/`）。

### 两个必须加的保护

```js
// 图只在内存里，刷新就没了——拦一下
window.addEventListener('beforeunload', e => {
  if (Object.keys(picked).length) { e.preventDefault(); e.returnValue = ''; }
});
```

以及**导出后不要清空已选**，用户可能想改一个再导一次。

---

## 六 · 收尾

用户填完、导出之后：

1. 跑 `unpack.py`（如果走了下载那条路）
2. 确认 `产出/素材/` 里的文件名对得上素材槽
3. 重跑 deck 脚本——有图的用真图，没图的自动回退到姓名卡，不用改代码

**文件名就是接口**：`P39-1.jpg` 放到 `P39` 页第 1 个槽位。
不要在代码里写死图名。

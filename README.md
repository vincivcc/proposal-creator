# proposal-creator

给 Claude Code / Codex 用的「写方案」技能。丢一个客户 brief 进去，出来一套交付物：
**逐页内容 + 可编辑的 PPT + 讲稿 + 换图清单**。

写给公关、广告、品牌方做提案的人。客户多为美妆、奢侈品、零售品牌。

---

## 解决什么问题

写一份 40–50 页的提案，实际耗时不在「想创意」，在四件琐事上：

1. **来回确认。** 逻辑对不对、内容行不行、数字准不准——改到第三轮发现第一轮方向就偏了。
2. **数字不敢用。** 每个数据都得回去翻来源，翻不到又舍不得删。
3. **排版返工。** 内容全写完了才做 PPT，发现风格不对，四十页重做。
4. **PPT 和讲稿对不上。** PPT 上字太多，讲的时候又找不到重点。

这个技能把流程切成五段，每段结束停下来让你确认（**三个硬卡点**），
所以返工永远发生在最便宜的时候：

```
① 提纲 / storyline ──→ 【卡点1 · 审逻辑】
② 每页具体内容    ──→ 【卡点2 · 审内容】
③ 数据与预算核对  ──→ 【卡点3 · 核数字】
④ 风格与素材 → 样稿 → 全案 PPT
⑤ 讲稿 + 换图清单
```

## 安装

**Claude Code 和 Codex 读的目录不一样**，两边互不读对方的：

| 工具 | 个人级 | 项目级 | 手动调用 |
|---|---|---|---|
| Claude Code | `~/.claude/skills/` | `.claude/skills/` | `/proposal-creator` |
| Codex | `~/.agents/skills/` | `.agents/skills/` | `$proposal-creator` |

只用一个工具的话，clone 到对应目录就行：

```bash
# Claude Code
git clone <本仓库地址> ~/.claude/skills/proposal-creator

# Codex
git clone <本仓库地址> ~/.agents/skills/proposal-creator
```

**两个都用，用软链接装一份**——省得两边各存一份，改了一边忘了另一边：

```bash
git clone <本仓库地址> ~/.claude/skills/proposal-creator
mkdir -p ~/.agents/skills
ln -s ~/.claude/skills/proposal-creator ~/.agents/skills/proposal-creator
```

装完之后不用注册，说「帮我写个方案」「有个比稿」这类话就会自动生效。

> 技能正文里所有脚本路径都写成 `$SKILL/scripts/...`，`$SKILL` 由正文开头那条
> `ls` 命令现场定位，所以装在哪、装在几个地方都不影响。

**依赖**：Python 3，以及 `python-pptx`、`Pillow`、`numpy`。

```bash
pip install python-pptx Pillow numpy
```

背景合成和 PPT 生成跨平台可用。**人物姓名卡的字体文件是 macOS 路径**，
其他平台会自动退回默认字体（不崩，但中文会变方块）——不用这个功能就无所谓。

## 怎么用

直接说人话就行：

> 帮我写个方案，客户是 XX，brief 在 `~/Desktop/brief.pdf`

它会先打印完整流程，告诉你现在在哪一步，然后开始。

### 出来的东西

```
<项目目录>/
├── 01-提纲-storyline.html      提纲 + 逻辑理由 + 反馈位
├── 02-内容-*.html              逐页内容
├── 03-数据与预算核对清单.html   逐条数字的来源与可靠性，给你打勾
├── 04-风格与素材.html          背景 / 配色 / 字体单选（带预览）+ 逐页素材上传
├── 全案-v1.pptx                可编辑的 PPT
├── 讲稿.html                   逐页「放什么字」+「怎么讲」
└── 换图清单.html               每个占位换成什么、从哪来
```

### 三件它会主动做的事

- **所有提问都走 HTML，不在对话框里问。** 问题攒成一批，能勾选、能填、
  能直接上传图片、能一键导出。省掉一问一答的往返。
- **PPT 上只留精简后的字，讲解要点全进讲稿。** 讲稿从 .pptx 直接读内容生成，
  永远不会和 PPT 脱节。
- **每排完一页跑自检**，逐页报「文字溢出」和「越界」，修到 0 才交给你。

## 内置的写作底线

这个技能最花心思的部分，是它**不肯做**的事：

| 底线 | 具体表现 |
|---|---|
| **不编数据** | 找不到来源的直接写「未找到公开来源」，不用推测填补。每个数字标可靠性等级 |
| **不抄创意** | 竞品方案只用作效果背书，不搬创意。背景图全部用 numpy 现算，无版权可商用 |
| **不替你定预算** | 推算值标明是推算值，预算必须你审核 |
| **不承诺效果** | 效果数字只做参考量级，不作为 KPI 承诺依据 |
| **不写执行细节** | 讲「谁」和「为什么是他」，不讲「他到场做什么」 |
| **不编占位符** | 团队配置、相关案例这类只有你有的信息，留「待你填」，不用假内容填满 |

这些规则写在 `references/红线与边界.md`，可以改——但改之前想清楚为什么有它们。

## 安全说明

**这个技能的 frontmatter 只有 `name` 和 `description` 两个字段。**

这是刻意的。SKILL.md 是个开放标准，好几个工具都读，但**只有这两个字段是
确定通用的**——其余（`allowed-tools`、`license`、`metadata` 等）都是某个工具
或某条分发通道的扩展。这个技能要跨工具用，所以能靠字段表达的信息全压进
那两个字段，其余一律写正文——正文是纯 markdown，到哪个工具都一样。

顺带说一句，**装别人的 skill 之前，先看它的 frontmatter**。如果里面有
`allowed-tools`，那个字段声明的东西会被直接授予，**不受工作区信任弹窗保护**。
本技能不需要它。

技能会读写你本机的文件、跑 Python 脚本、联网搜索。素材上传走浏览器的
File System Access API，**图片只写进你本机的项目目录，不上传任何外部服务**。

## 改它

| 症状 | 改哪里 |
|---|---|
| 该触发时没触发 | `SKILL.md` 的 description，补触发词 |
| 每次结果不一样 | 流程有歧义，把那一步写具体 |
| 排版老出问题 | 改 `scripts/kit.py`，别在 deck 脚本里绕过去 |
| 正文越改越长 | 加新内容前先删等量的旧内容——每条都会在每次触发时消耗上下文 |
